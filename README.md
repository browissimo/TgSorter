# TG Sorter — ручная фильтрация Telegram-каналов

Android-приложение для быстрой последовательной сортировки большого списка Telegram-каналов на **«+»** (подходит) и **«−»** (не подходит).

Сценарий работы:

```
Открыть в Telegram → посмотреть → назад → + / − → следующий канал
```

Приложение **полностью автономно**:

- нет сервера, API, Firebase и облачной БД;
- нет Telegram Bot API и MTProto, нет логина в Telegram;
- нет даже разрешения `INTERNET` в манифесте, поэтому выйти в сеть приложение не может;
- все данные лежат в локальной SQLite-базе (Room) на телефоне;
- Telegram открывается только через Android Intent (`tg://resolve?domain=…`, запасной вариант — `https://t.me/…`).

## Возможности

| Что | Как |
|---|---|
| Импорт | `.txt` через системный выбор файлов. Поддерживаются `@username`, `username`, `t.me/…`, `https://t.me/…`, `t.me/s/…`, ссылки на посты, `telegram.me`, `tg://resolve?domain=…` и несколько ссылок в одной строке. Пробелы, пустые строки и дубликаты удаляются (без учёта регистра), исходный порядок сохраняется. По итогам импорта показывается отчёт: сколько добавлено, сколько удалено дубликатов, какие строки не распознаны. |
| Просмотр | Крупный username, прогресс `318 / 842` и полоса выполнения. «Открыть в Telegram», большие кнопки **−** и **+**, «Пропустить», ← → для перехода к соседним каналам. Все кнопки внизу экрана, под большим пальцем. |
| Сохранение | Каждое нажатие сразу записывается в БД (транзакция Room). После закрытия, перезапуска или убитого системой процесса работа продолжается с того же канала. |
| Undo | Можно отменить 20 последних действий. История хранится в БД, поэтому отмена работает и после перезапуска. |
| Защита от ошибок | Без диалогов подтверждения. Двойной тап не отметит следующий канал «вслепую»: нажатие засчитывается только для канала, который сейчас на экране. |
| Навигация | ← / →, «Перейти к номеру…», «К последнему отмеченному», «К первому непросмотренному». |
| Пропущенные | «Пропустить» ставит статус `SKIPPED` и ничего не удаляет. Потом пропущенные можно разобрать отдельным проходом. |
| Результаты | Счётчики +, −, пропущенных и непросмотренных, отдельные списки по каждому статусу, поиск по username. Тап по каналу открывает его в Telegram. Можно скопировать один username или весь список, а также перенести канал в другой статус. |
| Экспорт | `positive.txt`, `negative.txt`, `skipped.txt`, `pending.txt` (по одному `@username` в строке) и `channels.csv` (`username,status,position`). Файл можно сохранить через системный диалог или отправить через «Поделиться». |
| Резервная копия | `channels.csv` можно импортировать обратно: отметки восстановятся. |
| Несколько списков | Главный экран показывает активный список со статистикой и все списки. Списки можно создавать, дополнять из TXT, переименовывать и удалять. |
| Конвейер (опция) | В меню экрана просмотра: «Сразу открывать следующий». После + или − следующий канал сразу открывается в Telegram, и тапов становится вдвое меньше. По умолчанию выключено. |
| Темы | Светлая и тёмная, переключаются вслед за системной настройкой Android. |

## Как получить APK

### Вариант 1. Android Studio (проще всего)

1. Установите [Android Studio](https://developer.android.com/studio) (любая свежая версия).
2. **File → Open** → выберите папку `TgSorter`. Дождитесь окончания Gradle Sync: первый раз скачиваются зависимости, это 3–10 минут.
3. Соберите APK:
   - **Build → Build App Bundle(s) / APK(s) → Build APK(s)** — получится debug-сборка `app/build/outputs/apk/debug/app-debug.apk`;
   - или, чтобы получить быструю оптимизированную сборку: откройте вкладку **Build Variants** и выберите `release`, затем снова **Build APK(s)**. Файл появится в `app/build/outputs/apk/release/app-release.apk`.
4. Скопируйте APK на телефон и откройте его. Android попросит разрешить установку из этого источника — разрешите.

Ещё вариант: включите на телефоне «Отладку по USB», подключите кабель и нажмите ▶ **Run** — приложение установится сразу.

> Для ежедневной работы ставьте **release**: он заметно плавнее debug-сборки.

### Вариант 2. Командная строка

Нужны JDK 17+ и Android SDK (путь к SDK задаётся в `ANDROID_HOME` или в `local.properties`: `sdk.dir=/path/to/Android/sdk`).

```bash
./gradlew assembleRelease        # app/build/outputs/apk/release/app-release.apk
./gradlew assembleDebug          # app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest      # юнит-тесты парсера и экспорта
```

### Вариант 3. GitHub Actions — без Android Studio

1. Создайте репозиторий на GitHub и загрузите туда содержимое папки `TgSorter`. Удобнее приватный: в проекте лежит ключ подписи, см. ниже.
2. Сборка запустится автоматически (workflow `.github/workflows/build-apk.yml`).
3. Откройте **Actions → Build APK → последний запуск → Artifacts → `tg-sorter-apk`**. Внутри zip-архива — готовый `app-release.apk`.

### Про подпись и обновления

Release-сборка подписывается ключом `keystore/tgsorter-release.jks` (параметры — в `keystore.properties`). Ключ сгенерирован специально для этого проекта. Он нужен затем, чтобы **новые версии устанавливались поверх старых без удаления приложения**: при удалении пропадёт прогресс.

- Если файла `keystore.properties` нет, release подписывается debug-ключом.
- Если публикуете репозиторий открыто, сгенерируйте собственный ключ и пропишите его в `keystore.properties`:

  ```bash
  keytool -genkeypair -keystore keystore/my.jks -storetype PKCS12 -alias tgsorter \
          -keyalg RSA -keysize 2048 -validity 10950
  ```
- Debug и release ставятся как **два разных приложения** (`com.tgsorter.app.debug` и `com.tgsorter.app`) с раздельными данными.
- Перед переустановкой с другим ключом сделайте экспорт `channels.csv`, а потом импортируйте его обратно.

## Как пользоваться

1. **Импортировать TXT** → выберите файл. Пример лежит в `sample/channels_sample.txt`.
2. **Продолжить просмотр**:
   - тапните **Открыть в Telegram** (или по самому username);
   - посмотрите канал и вернитесь назад. Самый быстрый способ вернуться — системный жест «предыдущее приложение» или двойной тап по кнопке недавних приложений;
   - нажмите **+** или **−**: приложение сразу перейдёт к следующему каналу.
3. Ошиблись — нажмите **Отменить** в строке над username.
4. **Результаты** — списки + и −, копирование и экспорт.
5. Когда непросмотренные закончатся, появится экран «Список завершён!» с итогами и кнопками экспорта. Оттуда же можно разобрать пропущенные.

### Если Telegram открывается, а канал — нет

Telegram по-разному открывает упоминания и ссылки:

- **@username** он сначала ищет в локальной базе.
- **Ссылку** (`t.me/…`, `tg://resolve`) каждый раз проверяет на сервере отдельным запросом. Если этот запрос не проходит (чаще всего из-за временного лимита Telegram на такие запросы), Telegram просто остаётся на списке чатов.

Проверить это просто: нажмите ссылку `t.me/telegram` внутри самого Telegram. Если она не открывается, проблема в Telegram, а не в TG Sorter.

Решение — меню **⋮** → **Как открывать каналы…** → **Поиск в Telegram**. Telegram откроется на поиске с подставленным username, останется нажать на найденный канал. Поиск идёт другим запросом и работает, даже когда ссылки не открываются.

Другие варианты в том же окне:

- **Проверить на @telegram** — открывает официальный канал выбранным способом;
- `tg://resolve` или `t.me` напрямую в Telegram;
- выбор приложения каждый раз;
- веб-превью `t.me/s/username` в браузере (работает только для публичных каналов с открытой лентой);
- внизу окна — какой Telegram найден и какие приложения перехватывают ссылки.

**Стек:** Kotlin 2.1, Jetpack Compose (Material 3), Room 2.6 + KSP, Navigation Compose, ViewModel + StateFlow, minSdk 26 (Android 8.0), targetSdk 35.

**Архитектура:**

```
UI (Compose) → ViewModel (StateFlow) → ChannelRepository → Room
```

- Экран подписан на Flow из Room, поэтому любое изменение в БД сразу отражается в интерфейсе.
- Каждая отметка — одна транзакция: запись в историю (для Undo), смена статуса и перевод указателя на следующий канал.
- Действия выполняются строго последовательно (Mutex), поэтому быстрые нажатия не создают гонок.

### Модель данных

| Таблица | Поля |
|---|---|
| `channel_lists` | `id`, `name`, `createdAt`, `lastOpenedAt`, `currentPosition` (где пользователь остановился) |
| `channels` | `id`, `listId`, `username`, `position` (1…N, порядок из файла), `status` (`PENDING` / `POSITIVE` / `NEGATIVE` / `SKIPPED`), `reviewedAt` |
| `history` | журнал последних действий для Undo: прежний статус, прежняя позиция |

Индексы `(listId, position)` и `(listId, status, position)` обеспечивают мгновенный переход к следующему каналу даже на 10 000+ записей.

### Обработка ошибок

- **Telegram не установлен** — открывается `https://t.me/username`, если и это невозможно — показывается сообщение.
- **Некорректный username** — такой канал не попадает в список ещё при импорте, а при открытии дополнительно проверяется.
- **Файл пустой, повреждён, бинарный, больше 20 МБ или в нём нет ни одного username** — показывается понятный диалог с примерами нераспознанных строк.
- **Файл в кодировке UTF-8, UTF-16 или Windows-1251** — определяется автоматически.
- **Ошибка записи в БД** — показывается сообщение, приложение не падает.
- **Все каналы обработаны** — открывается экран «Список завершён!».

### Изменение схемы БД

Destructive-миграции намеренно отключены, чтобы данные не потерялись. Если меняете сущности, повысьте `version` в `AppDatabase` и добавьте `Migration`. Схемы сохраняются в `app/schemas/`.
